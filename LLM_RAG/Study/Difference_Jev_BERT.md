* "BERT랑 같은 거 아니냐"는 말이 나오는 이유는 둘 다 **글을 만들어내지 않고 판단 결과만 돌려주는 모델**이기 때문입니다.
* 실제 차이는 모델 구조가 아니라 **쓰는 방식**에 있습니다. 다만 Jev는 내부 구조를 공개하지 않아서, 속이 BERT와 닮았는지는 아직 아무도 확인할 수 없습니다.

## 차별점 3가지

**1. 업무마다 모델을 새로 학습시키지 않음**
- BERT: 피싱 탐지, 문의 분류처럼 업무가 하나 생길 때마다 라벨 데이터를 모아 모델을 따로 학습시켜야 합니다. 업무가 10개면 모델도 10개가 됩니다.
- Jev: 모든 고객이 같은 모델(`jev-1.13.0`) 하나를 공유합니다. 무엇을 판단할지는 실행할 때 질문 문장으로 알려줍니다. 고객 데이터로 추가 학습도 하지 않습니다.
- 그래서 판단 기준이 바뀌면 질문 문장만 고치면 됩니다. 비교 실험에서 라우팅 정책을 바꿨을 때 Jev는 바로 반영했고, BERT 계열은 예전 규칙을 계속 적용했습니다.

**2. 정해진 형식으로만 답함**
- 질문 유형은 세 가지입니다.
  - Choice: 보기 중 하나를 고름
  - Score: 점수를 매김
  - Noul: 예/아니오를 확률로 답함
- 답은 항상 "선택지 + 확률" 형태라서 프로그램이 결과를 바로 받아 쓰기 좋습니다.

**3. 질문을 잘게 쪼개 동시에 묻는 방식에 맞춰져 있음**
- 질문 30개를 한꺼번에 던져도 1개를 물을 때와 비슷한 시간(약 150ms)에 처리됩니다. 기존 분류기는 분류 항목이 늘어나는 만큼 비용도 같이 늘어납니다.
- 최종 판단은 모델이 아니라 개발자 코드에서 조합하도록 설계되어 있습니다.

## 실제 성능에서 확인된 점

| 비교 항목 | 결과 |
|---|---|
| 고객 문의 77종 분류(Banking77) | 학습시킨 소형 BERT 계열 93.2% vs Jev(학습 없이) 80.1% |
| 피싱 메일, 한 번에 물었을 때 | Jev 약 60%대로 낮음 |
| 피싱 메일, 질문 5~8개로 쪼개고 가벼운 분류기로 합쳤을 때 | Jev 94~95% |
| 확신도의 정확성 | Jev는 평균 88% 확신하지만 실제 정답률은 약 80% → 실제보다 자신 있게 답하는 경향 |

정리하면, 라벨 데이터가 충분하고 판단 기준이 고정된 업무라면 **여전히 학습시킨 BERT가 더 정확하고 저렴합니다.** Jev가 유리한 경우는 라벨 데이터가 없을 때, 기준이 자주 바뀔 때, 여러 판단을 한꺼번에 돌려야 할 때입니다.

## 판단 시 유의할 점

- 모델 크기, 내부 구조, 학습 데이터가 모두 비공개입니다. 개발사(TypeSafe AI)는 "새로운 구조"라고만 밝히고 있습니다.
- 공식 홈페이지의 "193배 빠르고 비용은 444분의 1"은 회사 자체 측정치입니다. 외부 검증에서는 Haiku 4.5 대비 약 2.9배 빠르고 약 12배 저렴한 수준이었습니다.
- 질문을 쪼갰을 때의 95% 성능이 모델 자체의 실력인지, 질문을 잘 쪼갠 설계 덕분인지는 아직 구분되지 않았습니다.
- 즉, 사내 도입을 검토하신다면, 판단 기준이 자주 바뀌는 업무(문의 분류, 컴플라이언스 1차 검토 등)를 골라 우리 데이터로 정확도를 먼저 재 보시는 게 안전합니다.확신도 점수는 그대로 믿지 말고 따로 보정해서 쓰셔야 합니다.
