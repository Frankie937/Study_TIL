### hermes agent 강점
	- memory 기능이 너무 좋음 (메모리 업데이트 너무 잘함 , 코딩 룰, 컨벤션 등 잘 적용해 줌) -> 메모리를 쌓는 방식이 좋다는 의미 (open claw랑 비교를 해봤을 때, 기억하라고 했던 부분들을 업데이투러=
	- hermes skill - 8만 7천개가 있음 (안정성 보장이 되지 않기 때문에 주의해야 함, built-in skills 좋은 것 많으나 주의하면서 사용하기) 
	- 단순하게 자동화를 돌릴 수 있는 게 아니라 자는 시간에도 퀄리티가 높은 코드를 내는 에이전트, 명령어 자체도 에이전트가 내림  (이제 병목이 사람)
	- cron job 사용 - 주기적으로 실행 
		-> 예를 들어, 특정 프로젝트 코드에 5분에 한 번씩 결함을 찾아서 해결해달라고 요청  
		-> 클로드 루프랑 차이는? 반복수행이라는 건 차이가 없지만, 클로드 루프는 컨텍스트가 계속 쌓이지만 cron job은 context 초기화가 됨

* SOT(Source Of Truth) 
	- 예를 들어, 프로젝트의 목적/ 아키텍처/ db 스키마/ 유저 시나리오/ 코딩 룰(코드컨벤션) / api 스키마/ 스펙문서 등 쉽게 말해서 다양하게 기준점들을 만들어내는 것 -> 이런 부분을 문서로 만들어내는 것!!
	- 비전공자라고 해도 본인이 설명할 수 있는 것부터 최대한 풀어서 문서로 기준들을 만들어내면 됨!!! 
	- 결함을 찾으라는 기준에 대해서는 범위가 너무 넓음. SOT안에서의 결함을 찾으라고 하면 범위가 한정되기 때문에 더 정확하게 찾아냄
	- 브레인크루 팀안에서도 계속 SOT같은 md 문서들을 계속 깎아 냄. execution은 ai가 해주니
	- 코드변경되면 ADR 문서가 나온다고 생각

* SOT와 wiki는 다른 것
